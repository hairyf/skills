# 编排模式（敏捷 / 瀑布）

本 skill 支持两种模式，开工时必须二选一。核心区别：**瀑布先设计后开发，敏捷先交付后完善**。

## 敏捷模式 (Agile)

适合：MVP、原型、中小型软件、单页/工具、需求模糊或可边做边验证。

### 工作流

1. bpm 澄清目标、范围、验收标准（一次对话内，≤3 个问题；能推断的直接开工）。
2. design 产出一页轻量 spec（目标、范围、关键流程、验收标准、优先级），用户快速确认；**不写长文档**。
3. 拆垂直 slice：每个 slice 是一个可演示的功能（如"登录页"、"列表页"），不按技术层拆（如"先写数据库"）。
4. 每个 slice：领域 Agent 实现 → qa 快速验证 → 演示给用户 → 确认后进入下一个 slice。
5. 契约按需维护：只有跨 slice 共享的 ID/命名才写入 `contracts/contracts.json`，不为契约而契约。

### 规则

- 每个 slice 必须在本会话内可演示，禁止"先做完再一起看"。
- 用户确认前不堆砌下一个 slice。
- 需求变化欢迎：新需求切新 slice，不阻塞当前 slice 交付。

## 瀑布模式 (Waterfall)

适合：大型/多模块项目、重资产管线（游戏、企业系统）、强契约耦合、用户明确要求完整方案。

### 工作流

1. **契约先行**：锁版本矩阵（框架/引擎/依赖），维护 `contracts/contracts.json`。
2. **设计定稿**：design 产出完整文档（需求、范围、数据模型、UX、内容清单、数值、验收标准、优先级 P0/P1/P2），**用户审查通过前不写代码**。
3. **波次调度**（同时 ≤3 个子 Agent，数字按环境调整）：
   - Wave 1：骨架与最高风险项（架构 spike、资产概念、核心模块空壳）
   - Wave 2：量产角色并行（内容/后端/前端/资产）
   - Wave 3：集成 + QA（全量构建、自动化验证、门禁证据）
4. 每个阶段产物走用户门禁（证据形式见 SKILL.md 的 Gate 表）。

### 规则

- 定稿的只读产出（如设计文档）不得被后续 Agent 静默改写，改动走 bpm 变更请求。
- 版本矩阵一旦锁定，升级属于新任务。
- 跨模块引用一律走契约文件，不直接转发建议。

## 模式切换

- 敏捷中复杂度上升（契约冲突激增、并行需求膨胀）→ bpm 升级为瀑布，记录原因与切换点。
- 瀑布通常不降级为敏捷（设计已投入，降级浪费）；但可由 bpm 决定把后续内容切成 slice 增量交付。

## 返回契约

返回：所选模式、选择依据、该模式的当前阶段/迭代、下一个门禁。
